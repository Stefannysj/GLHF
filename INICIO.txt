GLHF - ETAPA 06 / PULIDO FINAL Y QA
===================================

1. OBJETIVO DE ESTA ENTREGA
La Etapa 6 cierra el desarrollo incremental de GLHF con QA responsive, mejoras finales de experiencia,
funcionalidades "wow" y preparación de despliegue en GitHub Pages.

2. FUNCIONALIDADES FINALES
- Máquina del tiempo: slider maestro de 7 eras. Mientras se arrastra cambia en tiempo real la paleta,
  tipografía y era activa; al soltar navega a la sección correspondiente.
- Progreso persistente: se guarda la última era visitada en localStorage y, al regresar, se ofrece
  continuar exactamente desde esa etapa.
- Konami Code: ↑ ↑ ↓ ↓ ← → ← → B A activa/desactiva el modo secreto "Player 2".
- PWA: manifest.webmanifest + sw.js para instalación y caché progresiva del contenido visitado.
- Botón INSTALAR: aparece únicamente cuando el navegador informa que la PWA puede instalarse.
- Barra cronológica, Hero dinámico, timeline interactiva, tilt/glow, scroll animations y reduced-motion
  de las etapas anteriores se mantienen.

3. LOGO - REGLA INALTERABLE

4. VISTA PREVIA
Extrae todo el ZIP y abre:

    index.html

La vista previa HTML muestra el contenido y las interacciones sin esperar a que Blazor cargue.
Las imágenes documentales externas requieren conexión a Internet.

5. EJECUCION BLAZOR
Requiere .NET 10 SDK. Desde la carpeta que contiene GLHF.csproj:

    dotnet restore GLHF.csproj
    dotnet watch --project GLHF.csproj

6. BUILD DE PRODUCCION

    dotnet publish GLHF.csproj -c Release -o artifacts/publish

El HTML canónico se genera desde Templates/ + Content/history.json antes del build.

7. GITHUB PAGES
El workflow incluido está en:

    .github/workflows/pages.yml

Flujo:
- checkout
- setup de .NET 10
- dotnet publish
- ajuste automático de <base href> con el base_path real del repositorio
- verificación de que exista un solo PNG llamado Logo_GgWp.png
- tools/qa.py sobre el artefacto publicado
- upload-pages-artifact
- deploy-pages

En GitHub: Settings > Pages > Source debe estar configurado como GitHub Actions.

8. QA LOCAL
Chequeo estructural sin dependencias externas:

    python tools/qa.py --root .

El QA valida IDs duplicados, anclas, assets locales, ausencia de loader, PWA, logo único y archivos prohibidos.

9. RESPONSIVE VALIDADO
Se revisó el HTML/CSS/JS entregado en Chromium headless en los siguientes viewports:
1920x1080, 1440x900, 1024x768, 820x1180, 680x960, 430x932, 390x844 y 320x568.
Resultado: 0 px de overflow horizontal en todos.

10. ACCESIBILIDAD

- Regiones y estados ARIA.
- prefers-reduced-motion neutraliza Hero automático, parallax y reveals decorativos.
