GLHF - ETAPA 01 / BASE Y ESTRUCTURA
=================================

1. VISTA PREVIA INMEDIATA
Extrae TODO el ZIP. Abre index.html en el navegador.
Es una vista previa HTML: no ejecuta C# ni pretende ser un build de Blazor.
Todos los textos, enlaces de seccion y referencias son accesibles.
El unico PNG esta en wwwroot/assets/Logo_GgWp.png.

2. EJECUTAR EL PROYECTO BLAZOR
Instala el SDK .NET 10 (no solo el Runtime) desde la pagina oficial:
https://dotnet.microsoft.com/es-es/download/dotnet/10.0
Abre una terminal en la carpeta que contiene GLHF.csproj y ejecuta:

    dotnet --version
    dotnet restore GLHF.csproj
    dotnet watch --project GLHF.csproj

URL del perfil de desarrollo: http://localhost:5180
Para iniciar sin watch:

    dotnet run --project GLHF.csproj

No abras wwwroot/index.html con doble clic: ese archivo requiere el runtime
que genera .NET. Usa la vista index.html de la raiz o el servidor de .NET.
Al ejecutar correctamente Blazor, el pie indica "Navegacion C# activa".
El contenido del museo permanece visible aunque WASM tarde en arrancar.

3. ESTRUCTURA
index.html                       Vista previa HTML en la raiz.
GLHF.csproj                      Aplicacion Blazor WebAssembly .NET 10.
Program.cs / App.razor            Entrada y montaje de la isla interactiva.
Components/EraNavigator.razor     Navegacion y estado de era en C#.
Services/ArchiveCatalog.cs        Datos embebidos, sin backend ni API.
Content/history.json              Fuente unica del contenido editorial.
Templates/*.html                 Plantillas del museo.
tools/SiteBuilder/                Generador C# del HTML inicial.
wwwroot/index.html               HTML inicial de Blazor (generado).
wwwroot/assets/Logo_GgWp.png      Unico archivo de logo.
wwwroot/assets/css/site.css      Estilos estructurales, no diseno final.
wwwroot/assets/js/site.js        Puente a APIs del navegador.
wwwroot/assets/js/bootstrap.js   Inicio progresivo de Blazor, sin loader.
.github/workflows/pages.yml      Compilacion y publicacion automatizadas.
tools/Publish.ps1                Publicacion local con base configurable.
VALIDACION.json                  Resultados reales y validaciones pendientes.

Los archivos index.html se generan desde las plantillas y el catalogo.
No edites directamente esos dos index para cambios permanentes.
El generador se ejecuta al compilar; solo escribe cuando cambia el contenido.

4. PUBLICACION LOCAL
Desde PowerShell en la raiz del proyecto:

    ./tools/Publish.ps1 -BasePath "/"

Salida: artifacts/publish/wwwroot
Sirve esa carpeta por HTTP antes de publicar. Si ya tienes Python:

    python -m http.server 5181 --directory artifacts/publish/wwwroot

Abre http://localhost:5181 y verifica "Navegacion C# activa".
Para simular un repositorio llamado GLHF en un subdirectorio:

    ./tools/Publish.ps1 -BasePath "/GLHF/"
    New-Item -ItemType Directory -Force artifacts/preview/GLHF
    Copy-Item artifacts/publish/wwwroot/* artifacts/preview/GLHF -Recurse -Force
    python -m http.server 5181 --directory artifacts/preview

Abre http://localhost:5181/GLHF/

5. GITHUB PAGES
Sube el contenido del proyecto a la rama main de un repositorio.
En Settings > Pages > Build and deployment selecciona GitHub Actions.
El workflow compila C#, configura base href segun el sitio y publica SOLO
artifacts/publish/wwwroot. No se necesitan secretos ni .env.
No se ha creado ni modificado ningun repositorio desde esta entrega.
No basta con subir archivos C# para que un navegador los ejecute:
la primera compilacion la realiza GitHub Actions o tu SDK local.
El visitante final no necesita instalar ni compilar nada.
No elijas Deploy from branch para verificar la version Blazor: la raiz
contiene una vista HTML deliberadamente estatica.

7. ALCANCE Y LIMITES
Incluido: HTML semantico, siete eras, 14 fichas textuales, seis ejes tematicos,
fuentes enlazadas, navegacion por anclas, esqueleto interactivo C# y workflow.
No incluido aun: Hero movil por esquinas, imagenes de juegos, parallax,
tilt/glow, comparador, mini-juego, PWA, sonido ni modo Konami.
No hay README.md, .env, Bootstrap, imagenes generadas ni PNG alternativos.

El proyecto C# NO pudo compilarse en el entorno de entrega: no habia SDK
y el acceso a la descarga estaba bloqueado. La vista HTML se reviso en Chromium
cargando los mismos bytes de HTML, CSS, JS y logo en memoria: la politica
del navegador de este entorno bloqueo abrir URLs HTTP y file://. Por ello,
no se validaron aqui el servidor local ni la apertura directa del archivo.
Esta revision no equivale a compilar ni ejecutar Blazor.
Se revisaron anchos de 320, 375, 390, 768, 1024, 1440 y 1920 pixeles,
mas emulacion de iPhone 13, Pixel 5 e iPad Pro 11, sin desborde horizontal.
Se verificaron anclas, referencias y contenido sin JavaScript. El puente
JS/C# solo se probo con un mock de JavaScript, no con C# compilado.
La publicacion real y las pruebas en dispositivos fisicos quedan pendientes.
Las cifras de eras y fichas describen esta edicion, no estadisticas de ventas.
