GLHF - ETAPA 02 / ESTILO VISUAL BASE
===================================

1. QUE SE IMPLEMENTO EN ESTA ETAPA
La Etapa 2 aplica la direccion visual base solicitada para GLHF:
- Dark mode como tema principal y unico tema visual de esta entrega.
- Paleta oscura con rojo inspirado en el logo, acento cyan y violeta secundario.
- Tipografia de sistema combinando display contundente, sans moderna y mono retro.
- Layout responsive refinado para mobile, tablet y desktop.
- Iconos/emojis usados de forma moderada como acentos de seccion.
- Scanlines y reticula muy sutiles creadas solo con CSS.
- Tarjetas, bordes, chips, estados de foco y superficies visuales coherentes.
- Navegacion movil horizontal y objetivos tactiles de al menos ~44 px.

No se implementa aun el Hero dinamico entre esquinas, porque corresponde a la Etapa 3.
Tampoco se incorporan aun imagenes reales de juegos ni tilt/glow avanzado de la
coleccion, ya que forman parte de etapas posteriores.

2. LOGO
Se mantiene UN SOLO PNG en todo el proyecto:

    wwwroot/assets/Logo_GgWp.png

No se genero ninguna variante, miniatura, recoloreado ni copia PNG adicional.
El encabezado, la portada, el footer y el favicon siguen usando el mismo archivo.
SHA-256 esperado:
462aac9a914a35ab7c67f873033ccb84ffb401537a5bc6a288154a93d41f9c33

3. VISTA PREVIA INMEDIATA
Extrae TODO el ZIP y abre index.html de la carpeta principal.
Esta vista previa HTML no ejecuta C#, pero permite revisar contenido y estilo visual.

4. EJECUTAR EL PROYECTO BLAZOR
Requiere .NET 10 SDK. Desde la carpeta que contiene GLHF.csproj:

    dotnet --version
    dotnet restore GLHF.csproj
    dotnet watch --project GLHF.csproj

Perfil de desarrollo: http://localhost:5180
Para iniciar sin watch:

    dotnet run --project GLHF.csproj

No abras wwwroot/index.html directamente como sustituto del servidor de Blazor.
Usa index.html de la raiz para preview o ejecuta el proyecto con .NET.

6. GITHUB PAGES
El flujo de publicacion de Etapa 1 se conserva. En GitHub:
Settings > Pages > Build and deployment > GitHub Actions.
El workflow compila y publica artifacts/publish/wwwroot con base href ajustado.

7. RESTRICCIONES MANTENIDAS
- No README.md.
- No .env.
- Sin Bootstrap u otros frameworks CSS pesados.
- Sin imagenes generadas por IA.
- Sin PNG adicionales.
- Sin pantalla de carga.
- El contenido permanece visible como HTML aunque Blazor todavia no haya iniciado.

8. ESTADO DE QA
Se ejecutan chequeos estructurales sobre HTML/CSS/JS, referencias locales, IDs,
anclas internas, existencia de assets, cantidad de PNG y hash del logo.
La compilacion C# solo puede darse por validada cuando se ejecuta con .NET 10 SDK.

9. SIGUIENTE ETAPA
Etapa 3: Hero dinamico.

transicion suave, definiendo un disparador compatible con desktop y mobile.
